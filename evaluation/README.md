# Проверки JanaMen AI

Пакет Якова внедрён как **отдельный испытательный контур**. Качество нашей модели по 128 вопросам пока **не измерялось**. Проверка целостности набора и тесты оценщика не являются оценкой ИИ. Файлы `vendor/.../reports/release-calibration` получены вместе с пакетом и не содержат результатов нашего приложения.

## Что импортировано

Исходный ZIP `JanaMen_Evaluation_Pack_v1.0.zip` сохранён распакованным без изменения содержимого в `vendor/janamen-eval-v1.0`. SHA-256 исходного архива:

```text
656360a7c45a97fc115c491e768d53d8bd67e5f75c75bdd83e31ce460d2de782
```

В нём 128 случаев RU/KK, 58 фрагментов БЗ, 34 группы происхождения, 74 dev и 54 verification. Нормы 5/7 дней и 50 000/60 000 тенге вымышлены. Они не добавлены в рабочую БЗ JanaMen. Сценарий аванса присутствует только в испытательном наборе; в продукте сейчас реализован отпуск.

Руководства оригинального пакета: [INTEGRATION](vendor/janamen-eval-v1.0/docs/INTEGRATION.md), [PROTOCOL](vendor/janamen-eval-v1.0/docs/PROTOCOL.md), [SCORING](vendor/janamen-eval-v1.0/docs/SCORING.md). Требования этих файлов описывают процедуру испытаний, а не разрешение скачивать модели или запускать нагрузку.

## Быстрая безопасная проверка

Из корня проекта:

```bash
node scripts/eval.mjs validate
node scripts/eval.mjs self-test
node --test --test-isolation=none --test-concurrency=1 tests/evaluation.test.mjs tests/assistant.test.mjs
```

Эти команды не запускают ИИ, не обучают и не скачивают модели. Node-тесты временно открывают только `127.0.0.1`, используют заглушку selector и сразу закрывают сервис. `self-test` проверяет сам Python-оценщик на искусственных ответах. Python 3 нужен только для оригинального оценщика; сторонние Python-пакеты не требуются.

## Отдельный адаптер

```bash
node scripts/eval-server.mjs
```

Он доступен только на `http://127.0.0.1:8989` и не устанавливает/не запускает модель. В рабочее приложение на порту 3000 тестовые маршруты не добавлены. Одновременно разрешён один вызов selector; второй получает 429. Завершение — `Ctrl+C`.

Адаптер проверяет оригинальный `manifest.json`, загружает статьи, `service-snapshots.jsonl` и конфигурацию ролей. Тексты эталонных ответов и категории из `cases.jsonl` в HTTP-адаптер не загружаются. Для каждого запроса отдельно применяются организация, роль, команда, одобрение и дата действия; затем выполняется детерминированный лексический поиск top-3. Снятая или закрытая статья не попадает в модель. `X-JanaMen-Eval-Case` выбирает только снимок, а не права. Поля `role`, `team`, `organization` тела не предоставляют доступ.

При запуске создаются четыре случайных тестовых токена в `evaluation/.runtime/tokens.env` с правами 0600. Они не связаны с паролями приложения и не должны попадать в Git. Перед использованием оригинального оценщика в другом терминале Bash:

```bash
source evaluation/.runtime/tokens.env
```

Токен нужен и для oracle. Доступные маршруты:

| Маршрут | Назначение |
| --- | --- |
| `GET /health` | Готовность адаптера; без заявления о качестве модели |
| `POST /__eval__/oracle` | Переданные разрешённые evidence → тот же selector, что в продукте |
| `POST /v1/assistant/answer` | Снимок → ACL/дата → поиск → selector |
| `GET /v1/knowledge/:id` | Исходная тестовая статья; закрытая и отсутствующая одинаково дают 404 |
| `GET /__eval__/business-state/leave` | Хэш настоящих бизнес-данных отдельной синтетической БД, если подключён reader |
| `GET /__eval__/business-state/advance` | 501: бизнес-сценарий аванса в продукте отсутствует |

CLI создаёт настоящую схему и вымышленные записи приложения во временной приватной SQLite, закрывает рабочее соединение и подключает только read-only reader. Хэш отпуска включает доступные роли кадровые записи, заявки с историей, вложения и документы. Временная БД удаляется при `Ctrl+C`. Это проверяет отсутствие изменений в синтетическом состоянии; рабочая `.data/asar.sqlite` не открывается. Тестовые роли не предоставляют к ней доступ. При использовании factory без `businessStateReader` endpoint возвращает 501, а не фиктивный успешный хэш.

## Ограничение текущей архитектуры ИИ

Сейчас модель **выбирает номер фрагмента**, а сервер формирует ответ из исходных предложений. Это не генеративная модель, обученная на политике компании. `server/assistant.mjs:selectEvidence` используется и продуктом, и адаптером. Текущие настройки selector: `temperature=0`, `max_tokens=3`, thinking отключён поддерживаемым параметром; модели показаны короткие превью. Это уменьшает нагрузку, но может терять важные условия и длинный контекст.

Пакет ожидает от генеративной модели raw JSON `{decision,answer,evidence_ids}`. Мы **не подменяем** настоящий raw-вывод selector серверным JSON: поле `raw_model_output` содержит, например, строку `"1"`, а `adapter_semantics` равно `evidence_selection_extract`. Поэтому соответствующий gate raw-формата оригинального пакета у этой архитектуры не пройдёт. Неполные цитаты, неправильный язык, недостаточное извлечение и ошибочный отказ тоже должны проявиться как ошибки проверки, а не скрываться правкой эталонов.

Ошибка/отсутствие модели в адаптере даёт 503, неверный raw-формат selector — 502. Успешный ответ поиска вместо ошибки ИИ здесь не подставляется. В продукте остаётся явно обозначенный поиск по БЗ. Неизвестная телеметрия не выдумывается: время первого токена и пик RAM не выдаются; токены берутся только из реального `usage`, если движок его вернул.

Контур `integrated` проверяет **изолированные фикстуры, их ACL/поиск и продуктовый selector**. Он не является полной оценкой поиска по рабочей БЗ, пользовательского интерфейса или всего HR-backend. Небольшие candidate pools набора не доказывают качество поиска по большой корпоративной базе.

## План запуска без нагрузки

Паспорт текущей конфигурации: [configs/qwen-local-low.json](configs/qwen-local-low.json). Зафиксированы GGUF-ревизия/SHA, CPU-профиль, контекст 1024 и фактический лимит selector в 3 токена. Неизмеренные параметры оставлены `null`. Один вопрос «Как подать заявку на отпуск?» вернул `local_model` с источником `leave-submit` за 15 секунд под лимитом 900 МБ и 80% одного CPU; это smoke-проверка, не p50/p95, не оценка 128 случаев и не доказательство прохождения порогов пакета.

Следующая команда только печатает план, HTTP-запросов нет:

```bash
python3 evaluation/vendor/janamen-eval-v1.0/evaluate.py run \
  --endpoint http://127.0.0.1:8989/__eval__/oracle \
  --model-metadata evaluation/configs/qwen-local-low.json \
  --mode oracle --split dev --scenario leave --language ru \
  --warmup 0 --repeats 1 --concurrency 1 \
  --out evaluation/results/leave-ru-plan
```

Не добавляйте `--execute` на слабом ноутбуке во время демонстрации. Реальные эксперименты проводить отдельно, по одной конфигурации, после фиксации БЗ, модели, профиля ресурсов и свободной памяти. Полную матрицу 12 конфигураций / 640 измерений автоматически не запускали. Для выбора по качеству потребуются фактические ответы и ручная RU/KK-разметка; сейчас нельзя утверждать, что найден минимальный проходной размер модели.

## База знаний приложения

Рабочие источники находятся в `server/knowledge.mjs`: это созданные командой демонстрационные инструкции по действующим формам, отпуску, ролям и обучению. Они не извлечены из официальных регламентов Jana Post и не подтверждают кадровые нормы компании. Презентация и ТЗ задают состав функций; они не содержат полной политики отпусков и выплат.

Каждая рабочая цитата теперь содержит ID, название, версию, происхождение, признак вымышленных правил, SHA-256 текста и путь `GET /api/knowledge/:id`. Рабочий backend проверяет доступ к статье по роли. Замена БЗ реальными документами требует согласовать владельца, период действия, роли и переводы; тестовые правила из пакета нельзя незаметно сделать корпоративными.
