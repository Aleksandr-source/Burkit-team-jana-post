# Испытания JanaMen AI

Здесь хранятся исходный набор испытаний, изолированный адаптер и результаты экспериментов. Рабочая конфигурация приложения — **Qwen3-0.6B Q4_K_M** из `scripts/ai-model.mjs`; код вызова — `server/ai/local-model-provider.mjs`. Старые отчёты относятся к зафиксированным в них моделям и настройкам.

`vendor/janamen-eval-v1.0` содержит пакет Якова: 128 случаев RU/KK, 58 тестовых источников, 74 случая dev и 54 verification. Правила в нём вымышлены и не добавлены в рабочую базу знаний. Аванс есть в испытательном наборе; в приложении реализован отпуск.

## Проверки без модели

Из корня проекта:

```bash
npm run eval:validate
npm run eval:self-test
node --test --test-isolation=none --test-concurrency=1 tests/evaluation.test.mjs tests/assistant.test.mjs
```

Команды не скачивают и не запускают модель. `validate` проверяет состав пакета, `self-test` — Python-оценщик на искусственных ответах. Для оценщика нужен Python 3 без дополнительных пакетов. Node-тесты используют временный локальный HTTP-сервис и заглушку модели.

## Проверка настоящего приложения

После установки модели отдельная команда обращается к настоящему движку и API:

```bash
npm run ai:check
```

Она сохраняет результаты в `evaluation/demo-qwen06/local-run` и использует отдельную временную базу. Это проверка демонстрационных случаев, а не полный benchmark. Её не следует запускать одновременно с показом или другими измерениями.

## Изолированный адаптер

```bash
npm run eval:serve
```

Адаптер доступен на `127.0.0.1:8989`. Он сам не устанавливает и не запускает модель. Тестовые токены создаются в `evaluation/.runtime/tokens.env`; они не связаны с учётными записями приложения и не публикуются. Для каждого запроса отдельно применяются организация, роль, команда, одобрение и дата действия источника. Заголовок `X-JanaMen-Eval-Case` выбирает снимок данных, но не предоставляет права.

| Маршрут | Назначение |
|---|---|
| `GET /health` | Готовность адаптера |
| `POST /__eval__/oracle` | Переданные разрешённые источники → продуктовый selector |
| `POST /v1/assistant/answer` | Снимок → доступ и дата → поиск → selector |
| `GET /v1/knowledge/:id` | Тестовый источник с проверкой доступа |
| `GET /__eval__/business-state/leave` | Хеш кадрового состояния временной SQLite |
| `GET /__eval__/business-state/advance` | 501: аванс не реализован |

Рабочая `.data` не используется. Код создаёт отдельную синтетическую SQLite и читает её состояние без записи во время оценки. Ошибка модели возвращается как ошибка; успешным ответом поиска она не подменяется.

## Как читать результат

Модель выбирает номер источника, а сервер выводит его текст. Текущие параметры: два полных источника, `temperature=0`, `max_tokens=16`, thinking выключен, таймаут 8 секунд.

Оригинальный пакет ожидает от модели JSON `{decision,answer,evidence_ids}`. Настоящий вывод нашего selector — число, которое сохраняется в `raw_model_output`. Поэтому критерий генеративного raw-формата нельзя считать пройденным только потому, что сервер собрал корректный ответ. `adapter_semantics: evidence_selection_extract` обозначает это различие.

Изолированные тесты не заменяют проверку поиска по рабочей базе `server/knowledge.mjs` и показ в браузере. Для сравнения конфигураций фиксируются модель, БЗ, параметры, оборудование, ответы и ошибки; неизвестные метрики остаются неизмеренными. Проверка схемы ответа и юнит-тесты сами по себе не подтверждают качество модели.
