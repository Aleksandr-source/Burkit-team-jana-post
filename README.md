# JanaMen

Единый HR-кабинет: профиль сотрудника, отпуск, обучение и ответы по базе знаний. Проект для кейса Digital HR на хакатоне Jana Post. Все сотрудники и кадровые правила в демонстрации вымышлены.

## Что можно показать

- **Личный кабинет:** ФИО, компания, должность, подразделение, руководитель, дата приёма, остаток и резерв отпуска, назначенное обучение и уведомления.
- **Отпуск:** сотрудник подаёт заявку → руководитель согласует → HR подтверждает. Есть история, отказ с причиной, отмена, вложения и печатное заявление с данными профиля.
- **Jana Academy:** уроки, тест и сохранение прогресса. HR создаёт, редактирует, публикует и назначает курсы. В новой демобазе сотрудник и HR уже начали по одному курсу.
- **JanaMen AI:** локальная модель выбирает источник из базы знаний; ответ сопровождается ссылкой на документ. Для неизвестных вопросов предусмотрен отказ.
- **Интеграции:** HR проверяет демонстрационный обмен с 1С:ЗУП и регистрирует согласованное заявление в макете Documentolog. Сотрудник получает уведомления об обработке документа.
- Интерфейс на русском, казахском и английском; темы, акцентные цвета, обои и размер текста.

Сотрудник видит свои данные, руководитель — разрешённые данные непосредственной команды, HR — сотрудников компании. Проверки доступа выполняются на сервере.

## Запуск из репозитория

Нужны **Node.js 24.11+**, npm и современный браузер. Установщик ИИ поддерживает Windows x64 и Linux x64. На Windows используйте терминал в папке проекта.

Первый запуск:

```bash
npm ci
npm run build
npm run ai:setup
npm start
```

`ai:setup` один раз скачивает модель (~484 МБ) и CPU-движок, проверяет SHA-256 и сохраняет их в `.local-ai`. Для установки нужен интернет; для последующей работы локального ИИ — нет. На Windows нужны штатные `curl.exe` и PowerShell. При ошибке об отсутствующей `VCRUNTIME140.dll` или `MSVCP140.dll` установите Microsoft Visual C++ Redistributable x64.

Откройте [http://localhost:3000](http://localhost:3000). Оставьте терминал открытым; остановка — `Ctrl+C`. При первом запуске сервер создаёт демонстрационную базу и учётные записи. Посмотреть данные для входа в другом терминале:

```bash
npm run accounts
```

| Учётная запись | Роль |
|---|---|
| `employee@janamen.demo` | Сотрудник |
| `manager@janamen.demo` | Руководитель логистики |
| `hr@janamen.demo` | HR |
| `outsider@janamen.demo` | Сотрудник другой команды |
| `secondmanager@janamen.demo` | Руководитель другой команды |

Пароли генерируются локально и хранятся в `.data/demo-accounts.txt`, исключённом из Git. Для одновременного показа ролей используйте разные браузеры или отдельные профили: обычные вкладки разделяют одну сессию.

Для следующего запуска достаточно **`npm start`**. После изменения интерфейса сначала выполните `npm run build`. Для разработки с обновлением страницы при сохранении файлов — `npm run dev`.

## Перенос на компьютер для показа

На Windows 11 x64 подготовьте проект командами выше и один раз проверьте сценарий целиком. 16 ГБ памяти дают запас для приложения и модели, но скорость ответа зависит и от процессора.

Можно перенести уже собранную папку: нужны `dist`, `server`, `scripts`, `package.json` и подготовленная `.local-ai`. Веса модели общие для Windows и Linux; движок и библиотеки должны соответствовать системе. `node_modules` готовому серверу не нужны. На целевом компьютере должен быть Node.js 24.11+, затем запускается `npm start`. При наличии файлов запуска также доступны `Start-Windows.cmd` и `Start-Linux.sh`.

`.data` содержит SQLite, вложения и историю демонстрации. Чтобы сохранить именно это состояние, остановите приложение и перенесите всю папку `.data`. Без неё при запуске создастся новая демонстрация. Не включайте локальные пароли, `.env`, `.data` и служебные ключи в публичный репозиторий. `dist/index.html` отдельно от сервера не запускает приложение.

## ИИ и база знаний

Используется конфигурация из `AI-branch`: **Qwen3-0.6B Q4_K_M** и **llama.cpp b8936**, без облачного AI API. Модель не дообучалась. Её версия, ссылка и контрольная сумма закреплены в `scripts/ai-model.mjs`.

Сервер отбирает доступные пользователю документы, передаёт модели до двух полных источников и просит выбрать подходящий либо вернуть отказ. Итоговый текст берётся из выбранного источника. Ссылки открывают сам документ с версией и контрольной суммой. База в `server/knowledge.mjs` написана командой для демонстрации и не является официальной кадровой политикой Jana Post.

В интерфейсе различаются режимы «локальная модель», «поиск по базе знаний» и подготовленная демонстрационная цитата. Последняя используется для точного вопроса «Как оформить отпуск». Если модель недоступна или превышено время ожидания, HR-функции продолжают работать, а ответ обозначается как поиск. Текущее ограничение ожидания модели — 8 секунд, одно обращение за раз.

Проверка установленных файлов без запуска модели:

```bash
node scripts/setup-ai.mjs --status
```

`JANAMEN_RESOURCE_PROFILE=auto` выбирает ограниченный профиль при небольшом объёме памяти. В `.env` можно задать `low`, `standard` или `off`; `off` оставляет поиск по базе знаний без нейросети. Запуск приложения сам ничего не скачивает.

Результаты экспериментов и команды проверки — в [evaluation/README.md](evaluation/README.md). Двуязычные испытания выявили ошибки; прохождение всех критериев качества не заявляется.

## Правила демонстрации и границы MVP

Отпуск считается в календарных днях включительно. Начальный остаток — 24 дня; при подаче дни резервируются, после подтверждения HR списываются. Отказ и отмена освобождают резерв. Праздники, ежегодное начисление и реальные нормы компании пока не учитываются.

После окончательного согласования доступна печать заявления с сохранённым снимком профиля. В браузерной печати можно выбрать PDF. Документ не имеет электронной подписи.

1С:ЗУП и Documentolog представлены работающими **mock-адаптерами**: данные и переходы статусов имитируются локально. Реальное подключение к установкам заказчика ещё предстоит. ТЗ допускает такой формат для хакатона; точки подключения показаны в [схеме архитектуры](docs/architecture.md).

## Стек и проверка

React 19, TypeScript, Vite, Tailwind CSS; Node.js HTTP API и SQLite; локальный llama.cpp. В собранной версии один Node-сервер отдаёт интерфейс и API. Данные остаются на диске компьютера, где запущен сервер.

```bash
npm test
npm run lint
npm run build
npm run eval:validate
npm run eval:self-test
```

Эти проверки не запускают нейросеть и не скачивают модели. Отдельная команда `npm run ai:check` обращается к настоящей модели и сохраняет результаты; её запускают отдельно от обычных тестов.
