# JanaMen

Хакатонный прототип единого HR-кабинета на основе исходного проекта команды. Сотрудник видит профиль, оформляет отпуск, проходит обучение и получает ответы из учебной базы знаний. Руководитель согласует заявки непосредственной команды, HR завершает согласование, добавляет сотрудников и редактирует курсы.

**Сотрудники, данные и кадровые правила вымышлены.** Знак Jana Post обозначает кейс хакатона. Прототип не является официальным сервисом или источником кадровой политики Jana Post.

Готовую сохранённую копию можно показывать без npm-зависимостей: на Windows x64 откройте `Start-Windows.cmd`, на Linux — `bash Start-Linux.sh`. Для Windows комплект включает отдельные Node.js и CPU-движок AI. Порядок переноса, пароли и системные библиотеки описаны в [docs/LOCAL-DEMO.md](docs/LOCAL-DEMO.md). В исходном репозитории тяжёлые локальные файлы не хранятся: это отдельный комплект для показа.

## Быстрый запуск на Arch Linux / Xfce

Нужны Node.js **24.11 или новее** с модулем `node:sqlite`, npm и современный браузер. Среда разработки проверяется на Node.js 26. Xfce не требует отдельных настроек.

```bash
node --version
npm ci
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Команда запускает сервер и Vite. При первом запуске создаются SQLite, вымышленные сотрудники и курсы. Для HR-приложения не нужны Firebase, Google OAuth, аккаунт Vercel или API-ключи.

При ручном запуске оставляйте терминал с `npm run dev` открытым во время работы. Завершение команды останавливает приложение. Если вход сообщает о недоступности сервера, сначала проверьте его запуск.

На компьютере команды готовая сборка также может работать фоновым пользовательским сервисом `janamen.service`. Проверка: `systemctl --user status janamen.service`; остановка перед ручным запуском: `systemctl --user stop janamen.service`. Локальная модель работает отдельным сервисом `janamen-ai.service` с лимитом 900 МБ; сервер — с лимитом 256 МБ. Этот фоновый запуск действует в текущей сессии Linux. После перезагрузки готовую версию можно запустить через `bash Start-Linux.sh`, без пересборки. Если сайт уже открыт и работает, вторую копию запускать не нужно.

В другом терминале получите учётные записи:

```bash
npm run accounts
```

Пароль генерируется локально при первом запуске. Информация для входа находится в `.data/demo-accounts.txt`; папка `.data` исключена из Git. Не публикуйте этот файл и не используйте пароль в реальных сервисах.

| Email | Роль | Что проверить |
|---|---|---|
| `employee@janamen.demo` | Сотрудник | Отпуск, Academy, ассистент, уведомления |
| `manager@janamen.demo` | Руководитель логистики | Заявки Алии; ограничения другой команды |
| `hr@janamen.demo` | HR | Окончательное согласование, сотрудники, редактор курсов |
| `outsider@janamen.demo` | Другая команда | Изоляция между сотрудниками |
| `secondmanager@janamen.demo` | Руководитель клиентского сервиса | Своя команда; отсутствие доступа к заявкам Алии |

Для одновременного показа ролей используйте разные браузеры, приватное окно или отдельные профили. Обычные вкладки одного браузера используют общую сессию.

## Локальный ассистент JanaMen AI без внешнего API

Вопросы и документы не отправляются облачному AI-провайдеру. Используется **Qwen3-0.6B Q4_K_M**, файл весов около 484 МБ (GGUF от bartowski), лицензия Apache 2.0, и локальный движок `llama.cpp`. Демонстрация ассистента проверяется на русском; качество казахского в этом режиме не подтверждено. Модель не дообучалась: приложение находит подтверждающие фрагменты и использует модель для их отбора.

На Arch Linux нужны `curl` и `tar` (обычно уже установлены):

```bash
sudo pacman -S --needed curl tar
npm run ai:setup
```

На Linux x64 установщик загружает готовый официальный CPU-движок `llama.cpp b8936` (архив около 14 МБ), включая варианты для старых процессоров. Для Windows x64 выбирается отдельный официальный CPU-архив с DLL. Компиляция не нужна. Версии зафиксированы, SHA-256 движка и весов проверяются до запуска. Первая загрузка требует интернета; предусмотрите около 1 ГБ свободного диска. После установки внешняя сеть для работы модели не нужна. Файлы сохраняются в `.local-ai`, исключённой из Git. На Windows для движка могут понадобиться системные библиотеки Visual C++ Redistributable x64. Потребление оперативной памяти больше размера весов; скорость зависит от процессора.

Для другой архитектуры или при необходимости собственной сборки доступен `node scripts/setup-ai.mjs --build`: нужны `base-devel`, `cmake`, `git`, `curl`, около 2 ГБ диска и дополнительное время на компиляцию.

```bash
npm run ai:start
```

После установки `npm run dev` и `npm start` также запускают модель автоматически; `ai:start` нужен для отдельной диагностики. Движок слушает только `127.0.0.1:8766`. Для настройки доступны `ASAR_AI_THREADS` (1–8, по умолчанию 2) и `ASAR_AI_PORT`. Состояние установки:

```bash
node scripts/setup-ai.mjs --status
```

JanaMen AI получает только разрешённые фрагменты учебных правил. Он показывает открываемые источники и отказывается отвечать без подходящей информации. Пароли и чужие кадровые записи не передаются модели. Финальный текст формируется из подтверждённых фрагментов базы знаний, чтобы модель не придумывала кадровые нормы.

Если движок не установлен, недоступен или занят, приложение честно обозначает **поиск по базе знаний**: это извлечение фрагментов, а не работа нейросети. HR-сценарий продолжает работать. Для показа нейросетевого режима заранее проверьте индикатор готовности.

## Собранная версия и данные

```bash
npm test
npm run build
npm start
```

`npm start` обслуживает готовый интерфейс и API одним сервером. Используйте адрес из терминала. SQLite, сессии и файлы сохраняются в `.data`; перезапуск не сбрасывает демонстрацию. Для резервной копии остановите сервер и сохраните всю `.data`, включая вложения. Удаление этой папки приводит к потере локальных изменений.

## После checkpoint: профиль, документ и курсы

Откройте **«Мой профиль»** в меню или нажмите аватар. Здесь находятся ФИО, компания, должность, подразделение, руководитель, дата приёма, табельный номер, контактный телефон и отпуск. HR открывает карточку сотрудника из списка «Сотрудники» и исправляет кадровые поля. Роли, пароли и остаток отпуска через эту форму не меняются. Изменение руководителя при действующей заявке требует сначала завершить или отменить её.

После последовательного согласования руководителем и HR в заявке доступна кнопка **«Печать / PDF»**. Сервер подставляет профиль, даты, число дней и историю решений в печатное заявление. Нажмите печать и выберите сохранение в PDF. Снимок профиля создаётся при окончательном согласовании, поэтому последующее исправление должности или имени не переписывает документ. Для ранее одобренных заявок снимок создаётся при первом открытии с соответствующей отметкой. Это демонстрационный шаблон, без электронной подписи и реального обмена с Documentolog.

**HR может создавать курсы:** Jana Academy → «Каталог» → «Создать курс». Добавьте название, описание, уроки, варианты теста, правильные ответы и проходной балл. Можно сохранить черновик, затем опубликовать и назначить сотрудникам. Назначение черновика недоступно. Прогресс и результат сохраняются в SQLite; правильные ответы обычному сотруднику не передаются.

При обновлении существующей базы демоадреса меняются на `@janamen.demo`; прежние адреса продолжают работать как алиасы. Пароли, сессии, заявки и обучение сохраняются. Технические имена SQLite и cookie оставлены совместимыми с предыдущей локальной версией.

## Режим для слабого компьютера

Для показа используйте готовый `dist` и `npm start`, без Vite и повторной сборки. Производственному серверу npm-зависимости не нужны. Тяжёлые загрузки автоматически не выполняются.

В `.env` доступен `JANAMEN_RESOURCE_PROFILE=auto` (по умолчанию). На компьютере с 8 ГБ памяти или меньше выбирается `low`: один поток CPU для ИИ, контекст 1024, batch 64/32 и ограниченное ожидание запуска. Профили: `auto`, `low`, `standard`, `off`. `off` оставляет HR и явно обозначенный поиск по знаниям без нейросети. `ASAR_AI_THREADS=1` задаёт число потоков вручную.

Для новой модели проверяется системный запас не менее 2 ГБ (`ASAR_AI_MIN_AVAILABLE_MB`, минимум настройки 1536 МБ), отдельно учитываются лимиты cgroup. На Linux также проверяются ограничения systemd и родительских групп. При системном запасе меньше 768 МБ или остатке лимита cgroup меньше 64 МБ модель останавливается. Блокировка предотвращает одновременную загрузку нескольких моделей. Приложение продолжает работать, если модель недоступна. Временные `process.lock.json` и `process.startup.guard` не переносятся в копии. После аварийного завершения внутри короткого startup guard сначала убедитесь, что процессов модели нет, и только затем удалите оставшийся guard.

Для Node сервера ограничен V8 heap до 256 МБ: это не общий предел RSS и не ограничение нативного движка. Для жёсткого ограничения памяти на Linux нужны cgroup/systemd; текущий запуск на компьютере команды использует отдельные ограничения для сервера и ИИ. Возможность нейросети работать на любом устройстве не гарантируется. Интерфейс не накапливает все посещённые страницы, сохраняет до 40 сообщений чата и обновляет данные реже, при видимой вкладке. Сборка Tailwind сканирует только активные HR-компоненты.

## Тесты ИИ и происхождение документов

В разделе ассистента раскрывается каталог источников. Рабочая БЗ — `server/knowledge.mjs`: демонстрационные инструкции команды по формам, отпуску, доступу и Academy. Это не официальные кадровые регламенты Jana Post. У цитат есть версия, происхождение, SHA-256 и проверяемая сервером ссылка.

Пакет Якова импортирован без изменения оригинальных фикстур: **128 случаев RU/KK и 58 тестовых источников**, включая аванс. Тестовые правила не добавлены в продуктовую БЗ; в самом HR-продукте реализован отпуск. Инструкция — [evaluation/README.md](evaluation/README.md).

```bash
npm run eval:validate
npm run eval:self-test
```

Эти команды не вызывают модель и не скачивают файлы. `npm run eval:serve` запускает отдельный контур на `127.0.0.1:8989`, с тестовыми токенами, ACL, датами, снимками и read-only хэшем отдельной SQLite. Рабочие данные не используются. Полный benchmark не запускается автоматически: качество по 128 вопросам и оптимальная конфигурация пока не измерены. Модель сейчас выбирает выдержки, поэтому её raw-вывод не соответствует ожидаемому пакетом генеративному JSON; это явно отмечается в отчёте адаптера.

Имена коммитов для GitHub Desktop и состав выполненных задач: [docs/COMMITS.md](docs/COMMITS.md). Коммиты автоматически не создаются.

## Реализованный объём

- Вход по email и паролю, серверные сессии в HttpOnly-cookie, выход из аккаунта.
- Три роли с проверкой доступа на сервере. Пользователь не назначает себе роль.
- Профиль: компания, отдел, должность, руководитель, дата приёма, остаток и резерв отпуска.
- Отпуск: руководитель → HR, история, причина отказа, отмена до окончательного одобрения.
- Общие серверные вложения, доступные другому уполномоченному аккаунту и устройству.
- Academy: два курса RU/KZ/EN, уроки, тест, сохранённый результат, редактор и назначения от HR.
- Уведомления об изменении заявок и событиях обучения.
- Ассистент с локальным движком, источниками и отказом вне базы.
- Переключение RU/KZ/EN, адаптивный интерфейс.
- Настройки внешнего вида: светлая/тёмная/системная тема, акценты и свой цвет, обои чата и собственный градиент, четыре размера текста. По умолчанию — тёмная тема с фиолетовым акцентом. Откройте «Настройки» → «Внешний вид» в боковой панели. Выход из аккаунта также находится в настройках. Изменения оформления применяются сразу и сохраняются в этом браузере; доступен сброс.

## Учебные правила отпуска

Остаток демосотрудника начинается с 24 дней. Считаются календарные дни включительно, без отдельного учёта праздников. Подача резервирует дни, подтверждение HR уменьшает остаток и освобождает резерв. Отказ и отмена освобождают резерв. Пересечения действующих заявок, прошлые даты и превышение доступного остатка отклоняются сервером.

Никто не согласовывает свой отпуск, включая HR. Для окончательного решения по отпуску HR нужен другой HR. У второго руководителя в демонаборе нет вышестоящего руководителя; он используется для проверки изоляции команд и согласования заявки HR. Основной показ проводите с `employee`, `manager` и `hr`.

Правила созданы для демонстрации и не являются юридической консультацией. Производственный расчёт по законодательству, праздникам, стажу и данным 1С не заявляется.

## Сценарий показа комиссии

1. Войти сотрудником: профиль, назначенный курс, доступные дни.
2. Подать отпуск на три будущих дня с вымышленным текстовым вложением. Показать резерв, этап и историю.
3. В другом профиле браузера войти руководителем, открыть вложение, согласовать.
4. Войти HR и подтвердить. У сотрудника показать уведомление, историю двух решений и новый остаток.
5. Под другим сотрудником показать отсутствие чужой заявки. Сервер также ограничивает прямые запросы по ID.
6. Завершить уроки и тест Academy, показать сохранённый результат. От HR открыть редактор и назначение курса.
7. Спросить помощника о порядке отпуска, открыть источник. Затем задать вопрос вне базы и показать отказ.
8. Переключить язык и показать мобильную компоновку.

## Интеграции и границы

Для HR доступен экран **«Интеграции»** и моковый API **1С:ЗУП / Documentolog**: просмотр сотрудников и остатков, предварительная синхронизация, регистрация согласованного заявления и имитация его обработки. Реальных соединений с сервисами нет. [Контракт и примеры API](docs/integrations.md). Архитектурные границы будущих адаптеров описаны в [docs/architecture.md](docs/architecture.md). Нет электронной подписи, юридически значимого документооборота, email/SMS и промышленной кадровой аналитики.

Старые Firebase-компоненты исходного проекта могут оставаться в исходниках, но новый HR-кабинет использует локальный сервер. Сайт друга не изменяется. **Статического Vercel-деплоя недостаточно для постоянной SQLite и локальной модели**: для общего сетевого доступа нужен процесс приложения на компьютере команды или сервере с постоянным диском. Локальная демонстрация работает через `localhost`.

## Проверки

`npm test` использует отдельные временные SQLite и настоящий HTTP-сервер. Проверяются изоляция сотрудников и команд, роли, последовательность решений, резерв, отмена, отказ, календарные даты, вложения между аккаунтами, серверная оценка тестов и HR-редактор. Тестовые пароли используются только во временной среде.

### Репетиция ассистента с Qwen3-0.6B

Вопрос **«Как оформить отпуск?»** возвращает дословный подготовленный ответ из
`demo-leave-walkthrough`. Метка «Демонстрационный ответ» отличает его от вывода
локальной модели. Источник содержит только демонстрационные правила; ссылка
открывает полный текст с версией и проверкой текущих прав доступа.

Для других вопросов модели передаются полные фрагменты двух доступных источников.
Она выбирает номер, сервер цитирует оригинал. Ожидание модели ограничено 8 секундами:
при превышении используется явно обозначенный поиск по базе знаний. Это резервный
режим, а не успешный ответ модели. Целевое время полного ответа API — до 10 секунд;
его необходимо измерять на компьютере, используемом для защиты.

После `npm run ai:setup` остановите запущенное приложение и выполните:

```bash
npm run ai:check -- evaluation/demo-qwen06/my-rehearsal
```

Команда запускает отдельный тестовый HR API с временной базой, последовательно
проверяет 16 вопросов дважды, JSON/HTML-ссылки для всех ролей, отключённую модель
и искусственно зависший runtime. Файлы сохраняются в новом каталоге; существующий
не перезаписывается. На Linux профиль с одним потоком проверяется так:

```bash
JANAMEN_RESOURCE_PROFILE=low npm run ai:check -- evaluation/demo-qwen06/my-low-rehearsal
```

Код завершения проверяет работоспособность, доступ и время. Точность надо смотреть
отдельно в `summary.json` (`correct / calls`) и `results.json`; успешное завершение
не означает 100% правильных ответов. Тестовые вопросы открыты и использованы при
